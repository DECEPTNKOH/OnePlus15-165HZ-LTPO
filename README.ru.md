# OnePlus 15: переключение частоты - DECEPTNKOH Preview

Первая итерация разработки завершена. Результат - экспериментальная
`v1.9.0-preview.1`, не стабильный релиз. Рабочая ветка
`fix/daemon-lifecycle` сохраняется; автоматического слияния в main, удаления
веток и публикации stable-релиза при закрытии итерации нет.

## Зафиксированная сборка

- Исходный коммит установленной версии: `87eb5e19122411066054316048b4dc03162b13bd`.
- ID: `OnePlus15-165HZ-LTPO`, versionCode: `10901`.
- Архив: `OnePlus15-165HZ-LTPO-v1.9.0-preview.1.zip`.
- SHA-256 ZIP: `2255ebdf4c237d3f28846bf036e71ffbe61ccbe528e03d2087cb503d7e51be42`.
- Проверено на CPH2747, `CPH2747_17.0.0.102(EX01)`, SukiSU.

Документационные коммиты после этой точки не меняют установленную сборку
и не требуют переустановки. Автообновления модуля отключены. Успешное
завершение CI на GitHub этим отчётом не удостоверяется.

## Подтверждено на устройстве

- XML прошёл валидатор и реально смонтирован поверх штатного файла.
- PID принадлежит vrrd.sh, а не постороннему приложению.
- После взаимодействия выбран режим дисплея 165 Гц.
- В простое выбраны 60 Гц при политике с верхней границей 120 Гц.
- Сохранена точка возврата для пользователя 0 со значением 7.
- Проверен возврат настройки 1 -> 7 при штатной остановке.
- Проверен повторный запуск правильного процесса демона.

## Не подтверждено

Физические 1 Гц панели не измерены независимо. В изученном референсном
драйвере min_fps возвращает программное состояние; test_te может возвращать
отфильтрованные значения, номинальную частоту либо значение sa_min_fps.
При software marker аппаратная регистрация TE IRQ может пропускаться.
Совпадение опубликованного исходника с бинарником ColorOS 17 не доказано.

Автономность, длительная стабильность, все сценарии камеры/игр/видео и реальное
удаление через менеджер не объявляются проверенными. Это ограничения
завершённой итерации, а не обещание продолжения работ.

## Что сохраняем

Работающий модуль и его служебные файлы, постоянный снимок настройки, списки
камер, один проверенный ZIP, снимок исходников и исходную резервную копию v1.8.
Снимок настройки сделан перед первым переключением новой версии, а не до
первоначальной установки старого модуля.

Старую резервную копию нельзя вслепую копировать обратно и запускать: в ней
осталась старая опасная логика работы с PID. Для выхода к штатной конфигурации
сначала отключают текущий модуль и перезагружаются; после аварийного завершения
настройку частоты проверяют отдельно.

## Что не делаем при завершении

Не прошиваем другое ядро, не сбрасываем биты adfr_config, не включаем test_te,
не используем Action/killall для горячей пересборки и не удаляем блокировку
работающего демона. Временные исследовательские копии удаляются только после
сохранения нужных отчётов и проверки точного списка. Другие проекты не трогаем.

KernelSU удаляет customize.sh после установки. Его отсутствие после успешной
установки ожидаемо; остальные отсутствующие файлы нельзя игнорировать при
проверке контрольных сумм.
