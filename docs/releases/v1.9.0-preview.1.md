# v1.9.0-preview.1 — DECEPTNKOH Preview

Экспериментальный pre-release, не стабильный выпуск. Первая итерация разработки завершена.

## Изменения относительно upstream v1.8

- Исправлена работа с устаревшими PID: посторонний процесс больше не блокирует запуск; удаление не отправляет сигнал по непроверенному PID-файлу.
- Добавлена блокировка жизненного цикла через flock, совместимая с Android mksh, и штатная остановка через флаг stop.
- Добавлены постоянная точка возврата настройки, привязка к пользователю Android и проверка восстановления чтением. Отсутствовавший ключ восстанавливается удалением.
- Перед монтированием XML обязательна проверка SAX + DOM. Ошибка парсера, тайм-аут, отсутствие JAR или ошибка преобразования останавливают применение патча.
- Добавлены проверка имён пакетов, экранирование для sed и контроль ожидаемых вставок.
- Добавлены общий запуск тестов, CI проверок и упаковка по списку файлов с манифестом SHA-256. Автообновления отключены.

## Проверено на устройстве

OnePlus 15 CPH2747, Android 17, сборка CPH2747_17.0.0.102(EX01), SukiSU: успешная загрузка, реальное монтирование проверенного XML, выбранный режим 165 Гц после взаимодействия и 60 Гц в простое при политике до 120 Гц, восстановление настройки 1 -> 7 и повторный запуск демона.

Перед созданием ZIP успешно завершились 65 unittest-проверок и исходные проверки sed/shell. Это не утверждение о текущем статусе GitHub CI.

## Ограничения и обновление

Физические 1 Гц панели НЕ подтверждены независимо: min_fps и test_te могут отражать программные значения. Автономность, длительная стабильность, все сценарии приложений и реальное удаление через менеджер не объявляются проверенными.

ID модуля сохранён для обновления v1.8. Требуется полная перезагрузка. Установщик этой preview ограничен CPH2747 на Android 17; другие окружения не заявлены. Перед обновлением сохраните конфигурацию: vrr.conf заменяется настройками пакета. Точка возврата фиксируется перед первым переключением новой версии, а не восстанавливает неизвестное состояние до установки v1.8.

Не используйте Action/killall для горячего обновления. Не включайте test_te и не меняйте adfr_config по этим диагностическим результатам. Не запускайте старый uninstall.sh из резервной копии v1.8.
